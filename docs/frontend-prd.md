# 前端需求文档 · v0.1

> 状态：**待评审**。评审通过前不改代码。
> 对应后端：SSE 流式（mock 回复，未接模型）。
> 接口定义见 `docs/api.md`。

## 1. 背景与目标

做一个能聊天的最小网页：用户输入一句话，页面显示回复。

**本期目标**：把"输入 → 请求 → 渲染 → 刷新不丢"这条链路走通，界面可看、异常不静默。

**明确不做**：登录、多会话、Markdown、语音、移动端 App。

## 2. 用户与场景

只有一个用户：你自己。典型场景：

1. 打开页面 → 看到历史或空状态 → 输入 → 看到回复；
2. 刷新页面 → 历史还在；
3. 后端没启动 → 页面明确告诉我"连不上"，而不是装作正常。

## 3. 页面结构

单页，垂直三段式，最大宽度 640px 居中：

```
┌──────────────────────────────┐
│ header：标题 + 状态提示        │
├──────────────────────────────┤
│ 消息列表（可滚动，自动吸底）    │
│   [用户]            ┌──────┐ │
│                     │ 气泡 │ │
│                     └──────┘ │
│   [助手] ┌──────┐            │
│          │ 气泡 │            │
│          └──────┘            │
├──────────────────────────────┤
│ 输入框                        │  [发送]
└──────────────────────────────┘
```

## 4. 功能需求

### FR-1 页面加载与历史恢复

- 页面挂载时请求 `POST /api/messages`（全 POST，见 `docs/api.md`）；
- 成功：按顺序渲染历史，滚动到底部；
- 失败：**显示错误条**（不是静默），内容形如"历史加载失败：HTTP 500"；
- 加载中：列表区显示"加载中…"，避免空状态闪烁；
- 竞态：若用户在历史返回前已发送消息，历史**不得覆盖**本地消息。

**验收**：后端关掉时刷新页面 → 能看到错误条；后端正常时 → 历史完整、无闪烁。

### FR-2 消息列表

- 每条消息有 `role`（user / assistant）和 `content`；
- 用户消息右对齐，助手消息左对齐，配色区分；
- 内容保留换行（`white-space: pre-wrap`），长单词/长 URL 可断行；
- 消息按时间顺序，最新在底部。

**验收**：连续发 10 条后，顺序正确、不重叠、不横向溢出。

### FR-3 输入与发送

- 多行输入框（`<textarea>`），占位文案"说点什么…"；
- **Enter 发送，Shift+Enter 换行**（已确认）；
- 高度自适应：1 行起步，最多长到 6 行后内部滚动；
- 输入为空（或只有空格）时按钮禁用；
- 提交后清空输入框，焦点保留在输入框；
- 输入长度上限 2000 字，超长时按钮禁用并提示。

**验收**：Space+Enter 无反应；Shift+Enter 只换行不发送；超长输入无法发送；输入 5 行时输入框自动变高。

### FR-4 发送中状态

- 请求期间：**输入框保持可用**（可以边等边打下一句），只禁用发送按钮；
- 按钮文案变为"发送中…"，头部状态从"就绪"变为"正在回复…"；
- 禁止重复提交：请求未完成时，按 Enter 或点按钮都不会再次发送；
- 请求结束后**光标自动回到输入框**，可连续输入，不需要重新点击。

**验收**：快速连点 5 次只发 1 次；发送后光标仍在输入框，可以直接打下一句；等待期间输入的文字不会丢失。

### FR-5 错误处理

| 场景 | 表现 |
|---|---|
| 网络不通 / 后端未启动 | 助手气泡显示"连接失败，请检查后端" |
| `code: 1001`（输入为空/超长） | 气泡显示后端返回的 `message` |
| `code: 5000` | 气泡显示"服务内部错误" |
| 请求超时（>30s） | 气泡显示"请求超时" |

- 错误只影响当前这一轮，**不锁定输入框**，用户可以立刻重试；
- 失败的轮次不写入历史（后端已保证）；
- 错误消息**不**用红色大面积色块，用小字提示即可。

**验收**：杀掉后端再发消息 → 出现"连接失败"气泡，输入框立即可用。

### FR-6 滚动行为

- 新消息到达后，若用户**当前已在底部**，自动滚到底；
- 若用户手动向上翻看过历史，**不强制滚动**，改为显示"回到底部"按钮；
- 切换页面/刷新后，首次加载直接定位到底部（不做动画）。

**验收**：向上滚动后发消息 → 视图不跳；点"回到底部" → 滚到最新。

### FR-7 空状态

- 无任何消息时，列表区居中显示一行灰字："说点什么，后端会原样回显。"
- 发送第一条后空状态消失，不再出现。

### FR-8 清空会话（本期不做，已确认）

本期不实现。需要后端 `DELETE /api/messages`，留到后续版本。

## 5. 状态模型

```
loading ──成功──▶ idle ──发送──▶ sending ──成功──▶ idle
   │                ▲                 │
   └──失败──▶ error │                 └──失败──▶ error（可立即重试）
```

| 状态 | 输入框 | 按钮 | 头部文案 |
|---|---|---|---|
| loading | 禁用 | 禁用 | 加载中… |
| idle | 可用 | 内容非空时可用 | 就绪 |
| sending | **可用**（可预备下一句） | 禁用（"发送中…"） | 正在回复… |
| error | 可用 | 可用 | 连接异常 |

## 6. 非功能需求

| 项 | 要求 |
|---|---|
| 首屏 | 本地环境 < 1s 可见内容 |
| 包体积 | gzip 后 < 100KB（当前 26KB） |
| 兼容 | Chrome / Safari 最近两个大版本 |
| 响应式 | 宽度 < 640px 时占满屏，气泡最大宽度 85% |
| 可访问性 | 新消息用 `aria-live="polite"` 播报；所有控件可 Tab 到达 |
| 文案 | 中文，不出现英文报错原文（除 HTTP 状态码） |
